1. Executive Summary & Product Positioning

AI0 Video Creator is a full-featured, cross-platform audio-visual content creation suite. It is designed to run cohesively across native desktop environments (powered by Tauri v2 + Rust + SQLite) and standardized reactive web browsers (via lightweight HTML5 LocalStorage fallbacks).

The studio streamlines the complete creative funnel—​going from core textual concepts to finalized, high-fidelity media assets—​through five specialized domain configurations (Scene Types):

  1. Short Video (short_video): Designed for 9:16 vertical fast-form videos ranging from 15 to 60 seconds.

  2. Story (story): Centered on horizontal narrative/plot-driven layouts with sequential scene templates.

  3. Dialogue (dialogue): Multi-role scenarios focusing on conversational structures, customizable roles, and voice-cloning configurations.

  4. Word (word): An educational visual flashcard generator pairing languages (English and Chinese) with phonetic annotations, example scripts, and video loops.

  5. Video Translation (video_translation): A localized audio-visual lip-synchronization workbench providing speech-to-text subtitle generation, AI translation (via modern Gemini client-side models), localized TTS synthesis, and LipSync voice-cloning video reconstruction.

This document represents the definitive technical specification and operational guidelines of the React/Tauri codebase as updated for the v2.1.0 release.

3. Database Schema & Migration Strategy

To support SQLite transitions without table lockouts, the system utilizes a lightweight migrations engine managed via the Tauri SQL Cargo plugin.

3.1. Database Entities & Relationship Map

  • video_projects: Holds the parent metadata of each audio-visual project, defining prompt constraints, scenes, status rules, and localized save directories.

  • vocabulary: Sub-table coupled to the word scene type, detailing words, phonetic definitions, multi-language transcriptions, prompt blueprints, and localized frame resources.

  • app_settings: Key-value map storing global environment configurations like Python installation paths, custom server ports, and color presets.

3.2. Full Schematic Schema (Tauri SQLite Core)

-- Parent Table: Video Projects Master Control
CREATE TABLE IF NOT EXISTS video_projects (
    project_uuid TEXT PRIMARY KEY,
    project_name TEXT NOT NULL,
    project_prompt TEXT,
    cover_image_path TEXT,
    create_time INTEGER NOT NULL,
    update_time INTEGER NOT NULL,
    project_status INTEGER NOT NULL DEFAULT 0,
    scene_type TEXT DEFAULT 'short_video' CHECK (scene_type IN ('short_video', 'story', 'dialogue', 'word', 'video_translation')),
    scene_config_id INTEGER,
    template_id INTEGER,
    project_path TEXT
);

-- Child Table: Vocabulary Content Modules for Language Learning
CREATE TABLE IF NOT EXISTS vocabulary (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_uuid TEXT NOT NULL,
    word TEXT NOT NULL,
    audio_path TEXT,
    index_char TEXT,
    example TEXT,
    image_path TEXT,
    phonetic_symbols TEXT,
    chinese_definition TEXT,
    data TEXT,
    prompt TEXT,
    video_path TEXT,
    ltx23_prompt TEXT,
    t2v_prompt TEXT,
    qwen_image_prompt TEXT,
    category TEXT,
    script TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    status INTEGER DEFAULT 1,
    chinese TEXT,
    FOREIGN KEY (project_uuid) REFERENCES video_projects(project_uuid) ON DELETE CASCADE
);

-- Key-Value Store: Core App Settings
CREATE TABLE IF NOT EXISTS app_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

3.3. Lifecycle Schema Migrations (Versions 1-11)

The application has migrated through 11 database versions, incrementally adding columns and constraints safely:

  • Version 1 (initial_setup): Creates the basic video_projects schema columns.

  • Version 2 (add_scene_columns): Appends scene_type, scene_config_id, and template_id columns to projects.

  • Version 3 (create_scene_tables): Mounts supporting entity systems (scene_config, scene_template, dialogue_role, word_detail).

  • Version 4 (add_vocabulary_table): Implements the optimized, comprehensive SQLite vocabulary management system.

  • Version 5 (add_settings_table): Hooks up global key-value app_settings persistency.

  • Version 6 (add_project_path_column): Inserts project_path string identifiers for direct native OS folder syncs.

  • Version 7 (support_video_translation_scene): Introduces video_translation into the project types, performing high-integrity SQLite schema rebuilding on video_projects table to update the CHECK constraint.

  • Versions 8 to 11 (fix_video_projects_translation sequence): Stepwise table recovery sequence ensuring backwards-compatible migration of active projects, safe-guarding existing user metadata while enforcing foreign key constraints.

4. Multi-Platform Storage Layer (Ad-hoc DB Adapter)

The front-end queries the database via an environment-aware interface (src/lib/db.ts). This structure routes requests natively through Tauri if system bindings are alive, falling back to local browser state when running in isolated preview frames.

import Database from "@tauri-apps/plugin-sql";
import { VideoProject, Vocabulary } from "../types";

let db: Database | null = null;
const isTauri = typeof window !== 'undefined' && !!(window as any).__TAURI_INTERNALS__;

export async function getDb() {
  if (!isTauri) return null;
  if (!db) {
    try {
      db = await Database.load("sqlite:main.db");
    } catch (err) {
      console.error("Failed to load SQLite via Tauri plugin-sql:", err);
      return null;
    }
  }
  return db;
}

export async function fetchProjects(): Promise<VideoProject[]> {
  if (isTauri) {
    const database = await getDb();
    if (database) {
      const result = await database.select<any[]>(
        `SELECT p.*,
        (SELECT image_path FROM vocabulary v
         WHERE v.project_uuid = p.project_uuid
         AND v.image_path IS NOT NULL
         AND v.image_path != ''
         ORDER BY RANDOM() LIMIT 1) as random_cover
        FROM video_projects p
         ORDER BY p.update_time DESC`
      );
      return result.map(p => ({
        id: p.project_uuid,
        name: p.project_name,
        prompt: p.project_prompt,
        coverImagePath: p.random_cover || p.cover_image_path,
        projectPath: p.project_path,
        status: p.project_status,
        sceneType: p.scene_type || 'short_video',
        createdAt: p.create_time,
        updatedAt: p.update_time,
      }));
    }
  }
  return getLocalStorageProjects();
}

5. Specialized Page Modules & Workbenches

5.1. The Dashboard (src/pages/Dashboard.tsx)

The standard control terminal displaying all visual pipelines. Let’s look at its structural blocks: * Interactive Project Creation: Opens a visual creation modal prompting for project name, an initial generation prompt, and a scene selector. * Layout Grid: Distributes projects dynamically in high-contrast visual cards featuring a responsive category badge, status indications (Draft, Editing, Animating, Finalizing, Completed), and cover frame thumbnails. * Filtering and Search System: Supports fuzzy keyword matching along with a dropdown selector to filter by creative types (short_video, story, dialogue, word, video_translation).

5.2. Project Detail & Workspace Router (src/pages/ProjectDetail.tsx)

Acts as a multi-module router that evaluates project.sceneType to dynamically adapt the workbench’s module options. * Launch Editor Control: Automatically directs the user to the correct editor. For video_translation, it routes the user to the specialized translation workbench: /translation?project_id={id}. For word, it presents a dedicated Vocabulary workspace module. For standard creative pipelines, it displays edit routes for AI Script, Visuals, Audio, and Timeline**.

5.3. Word & Vocabulary Workbench (src/pages/WordManagement.tsx)

An educational asset design screen centering English/Chinese dictionary components: * Index & Search Navigation: Lists vocabulary with an index character filter bar (A-Z keys) styled with high-contrast text tags. * Card Designer Deck: Lets the user edit the details of a flashcard, including definitions, voiceovers, examples, and background prompts. * Prompt Generators: Contains auto-prompters to quickly design Qwen detailed images or LTX2.3 video description scripts for the selected word in horizontal story structures.

5.4. Video Translation Workbench (src/pages/VideoTranslation.tsx)

A specialized translation editor featuring advanced audio-visual manipulation options:

  1. Project Bridge: Reads project_id from search params during load. Retrieves project configurations from the sqlite database while loading granular session snapshots (logs, synthesized media assets, models) from local storage.

  2. Media Stream Manager: Embeds standard React HTML5 video controls with frame-accurate timeline trackers.

  3. Auto Cover Frame Extraction: Leverages native video canvas contexts to dynamically draw the 1st frame on-the-fly and sync it back as the project’s cover thumbnail.

  4. Advanced Settings Deck:

    • Lip-Alignment Models: Lets users choose between models like LTX2.3 + LipSync-1.0 and standard wav2lip-high.

    • Voice Cloner Selector: Interactive voice cloning profiles (e.g., Sora DeepNarrator, Tony English Male, Chinese Sweet Female).

    • TTS Speed Control: Smooth sliders to modify output narration tempos.

  5. Visual Subtitle Timeline: Lists SRT dialogues mapped with starting and ending timestamps, allowing manual text adjustments.

  6. Pipeline Orchestrator: Runs full sequential translation pipelines—​from automated speech-to-text, Gemini text translation, voice cloning, and LipSync rendering—​with real-time system logs.

  7. Cloud & Local Save Controller: Includes a Save to AI Core Suite button, committing final media resources, updated subtitles, prompts, and cover thumbnails back to the central sqlite context.

6. AI Integration Specifications

The studio leverages client-side models proxying through secure APIs. All Gemini calls utilize the modern, unified @google/genai TypeScript client.

6.1. Gemini API Framework (src/lib/gemini.ts)

The API wrapper manages script synthesis, speech-to-text transcripts, and content translation:

import { GoogleGenAI } from "@google/genai";

// Initialize client safely on-demand
let aiClient: any = null;

function getGeminiSDK() {
  if (!aiClient) {
    const key = process.env.GEMINI_API_KEY || "";
    aiClient = new GoogleGenAI({ apiKey: key });
  }
  return aiClient;
}

/**
 * Text Translation proxy using gemini-2.5-flash
 */
export async function translateTextGemini(text: string, targetLang: string): Promise<string> {
  const ai = getGeminiSDK();
  const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash',
    contents: `Translate the following dialogue into native, colloquial, naturally aligned ${targetLang}, preserving subtitles SRT format and timings: \n\n${text}`,
  });
  return response.text;
}

7. Compilation & Deployment Guidelines

7.1. Native Package Build (Tauri Output)

To compile the system into standalone, lightweight .msi, .dmg, or .deb desktop products, execute the native build chain:

# Run standard development environment checks
npm run lint

# Package application assets via Vite and trigger Tauri compilation
npm run build
cd src-tauri
cargo build --release

7.2. Web Preview & Sandbox Deployment

For deployment in sandbox environments or web app containers, execute the web production build:

# Clear previous build directories
npm run clean

# Package web production distribution folder
npm run build

# Start preview server
npm run preview -- --port 3000 --host 0.0.0.5

7.3. Configuration Environment Variables (.env.example)

Ensure sensitive API credentials and ports are declared properly in the root environment template:

# API Credentials
GEMINI_API_KEY=your_gemini_api_key_here

# Services Host Ports Configuration
OLLAMA_HOST_PORT=11434
COMFYUI_HOST_PORT=8188
